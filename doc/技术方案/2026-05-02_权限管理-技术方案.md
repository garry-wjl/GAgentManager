# 权限管理（RBAC）技术方案

## 1. 目标与范围

- **目标**：基于现有六层 RBAC 代码，补充领域动作完整性、事务一致性、查询增强（userCount 填充、权限矩阵、去重），并完成时间字段毫秒精度统一，使权限管理模块达到可交付状态。
- **范围**：角色 CRUD + 权限配置 + 用户角色绑定 + 权限矩阵查询 + 用户权限去重查询 + 时间字段精度修正。不涉及权限资源/动作的动态 CRUD（通过初始化脚本预置）。
- **不涉及**：权限资源树/权限动作的新增编辑、数据级权限控制、临时权限/过期权限管理 UI、事件发布机制。

**共识要点**（来自设计决策确认）：
- Role 聚合根补充 `ensureNum()` 方法（num = "ROLE-" + 时间戳）
- deleteRole 不校验关联用户数
- assignPermissions 方法加 `@Transactional` 确保事务一致性
- UserRole/RolePermission 实体增加 `delete(operatorId)` 领域动作
- PermissionResource/PermissionAction 视为静态数据，不需要领域动作
- 不补事件发布逻辑
- getPermissionsByUserId 返回去重后的权限码列表
- 新增 `batchAssignUsers` 方法（一个用户关联多个角色）
- 角色列表查询时通过 `countByRoleId` 填充 `userCount` 字段
- 新增权限矩阵接口（PermissionMatrixVO）
- 所有 RBAC 表时间字段统一为 `DATETIME(3)` 毫秒精度

### 3.2 角色（role）

#### 3.2.1 领域模型

```mermaid
classDiagram
    class Role {
        <<aggregate root>>
        +Long id
        +String num
        +String createNo
        +String updateNo
        +String roleCode
        +String roleName
        +String description
        +Boolean isSystem
        +Boolean isEnabled
        +save(operatorId)
        +delete(operatorId)
        +enable(operatorId)
        +disable(operatorId)
        +ensureNum()
    }
    class RolePermission {
        <<entity>>
        +Long id
        +String num
        +String createNo
        +String updateNo
        +Long roleId
        +Long resourceId
        +Long actionId
        +String permissionCode
        +String grantType
        +create(roleId, resourceId, actionId, permissionCode, grantType)
        +delete(operatorId)
    }
    class UserRole {
        <<entity>>
        +Long id
        +String num
        +String createNo
        +String updateNo
        +Long userId
        +Long roleId
        +String assignType
        +Date assignTime
        +String assignUser
        +Date expireTime
        +create(userId, roleId, assignType, assignUser)
        +delete(operatorId)
    }
    Role "1" --> "*" RolePermission : has
    Role "1" --> "*" UserRole : has
```

| 对象 | 类型 | 属性 | 与其它对象关系 |
|------|------|------|----------------|
| Role | 聚合根 | id, num, createNo, updateNo, roleCode, roleName, description, isSystem, isEnabled | 聚合根 |
| RolePermission | 实体 | id, num, createNo, updateNo, roleId, resourceId, actionId, permissionCode, grantType | 属于 Role 聚合，通过 roleId 引用 |
| UserRole | 实体 | id, num, createNo, updateNo, userId, roleId, assignType, assignTime, assignUser, expireTime | 属于 Role 聚合，通过 roleId 引用 |

**聚合与边界**：
- Role 为聚合根，RolePermission 和 UserRole 为聚合内实体
- 跨聚合引用：resourceId 引用 PermissionResource，actionId 引用 PermissionAction，userId 引用 User
- 一致性边界：一次事务内只修改一个 Role 聚合

#### 3.2.2 领域规则

| 聚合/对象 | 规则类型 | 规则描述 | 违反时表达 |
|-----------|----------|----------|------------|
| Role | 不变性 | roleCode 全局唯一 | ROLE_CODE_ALREADY_EXISTS (1701) |
| Role | 业务规则 | 系统内置角色（isSystem=true）不可删除 | ROLE_IS_SYSTEM (1705) |
| Role | 业务规则 | 删除为逻辑删除（deleted=true） | — |
| Role | 业务规则 | num 为空时自动生成（ROLE-时间戳） | — |
| RolePermission | 不变性 | 同一角色对同一资源+动作组合唯一 | 数据库唯一索引 uk_role_resource_action |
| UserRole | 不变性 | 同一用户与同一角色关联唯一 | 数据库唯一索引 uk_user_role |
| RolePermission | 业务规则 | grantType 仅允许 ALLOW 或 DENY | — |
| UserRole | 业务规则 | assignType 默认为 DIRECT | — |

#### 3.2.3 领域动作

| 聚合/实体 | 领域动作 | 职责 | 前置条件 | 后置条件/规则 | 领域事件 |
|-----------|----------|------|----------|----------------|----------|
| Role | save(operatorId) | 保存/更新角色 | operatorId 有效 | num 已生成，createNo/updateNo 已更新 | — |
| Role | delete(operatorId) | 逻辑删除角色 | 非系统内置角色 | deleted=true，updateNo 已更新 | — |
| Role | enable(operatorId) | 启用角色 | operatorId 有效 | isEnabled=true，updateNo 已更新 | — |
| Role | disable(operatorId) | 禁用角色 | operatorId 有效 | isEnabled=false，updateNo 已更新 | — |
| Role | ensureNum() | 生成业务编号 | num 为空 | num = "ROLE-" + 当前时间戳 | — |
| RolePermission | delete(operatorId) | 逻辑删除权限关联 | operatorId 有效 | deleted=true，updateNo 已更新 | — |
| UserRole | delete(operatorId) | 逻辑删除用户角色关联 | operatorId 有效 | deleted=true，updateNo 已更新 | — |

```mermaid
sequenceDiagram
```

## 11. 其他

### 事务边界

- `assignPermissions` 方法标记 `@Transactional`，确保清空旧权限 + 写入新权限在同一事务内
- 其他方法为单步操作，不需要额外事务注解

### 权限矩阵构建逻辑

`getPermissionMatrix(roleId)` 的实现思路：
1. 查询该角色的所有 RolePermission，构建 `Set<resourceId, actionCode>` 的已勾选集合
2. 查询全部 PermissionResource，构建树形结构
3. 遍历资源树，为每个节点标记 `checkedActions`（该资源在角色中已勾选的动作编码列表）
4. 返回 `PermissionMatrixVO` 列表（通常只有一个元素，因为查询的是单个角色）

### 与用户管理模块的关联

用户管理模块中用户详情页展示关联角色（只读），通过 RoleGateway 接口跨域查询。RoleGateway 接口定义在用户管理技术方案中，由 RBAC 模块的 infra 层实现。
