## 1. 目标与范围

### 1.1 目标

- 提供模型注册能力，支持主流 LLM 提供商和自部署模型
- 实现模型启用/停用控制，为 Agent 模型选择提供数据源
- 提供模型列表筛选能力（按提供商、状态、关键词搜索）
- 建立模型连接参数管理体系（API endpoint、API key、timeout 等）
- Agent 删除前校验模型绑定关系，Agent 创建/编辑时获取已启用模型列表

### 1.2 范围

| 范围内 | 范围外 |
|--------|--------|
| 模型注册（提供商、名称、类型、连接参数） | 模型配额管理（TPM/RPM 限流） |
| 模型启用/停用 | 模型健康监控（调用统计、失败率） |
| 模型列表/详情/编辑 | 模型默认推理参数（temperature、max_tokens 等） |
| API Key 加密存储（AES） | 模型调用链路代理/网关 |
| 模型删除（禁用状态才可删除） | 普通用户端的模型管理功能 |
| Agent 创建/编辑时获取已启用模型列表 | 连通性测试 |

### 1.3 关键技术决策

| 决策点 | 方案 |
|--------|------|
| 模型参数范围 | 精简为连接参数：provider、modelCode、modelName、category、baseUrl、apiKey、timeout、description |
| 唯一约束 | modelCode 全局唯一（数据库唯一索引），与现有代码一致 |
| API Key 存储 | AES 对称加密存储，使用现有 AesEncryptor |
| API Key 展示 | 详情页脱敏显示（sk-****abcd） |
| HTTP 方法 | 仅 GET（查询）和 POST（增删改） |
| 错误码前缀 | 1401 起（PRD 约定），但现有 12xx 段已使用，沿用现有 |
| 连通性测试 | 本期不实现 |

### 3.2 Model（model）

#### 3.2.1 领域模型

```mermaid
classDiagram
    class Model {
        +Long id
        +String num
        +String modelCode
        +String modelName
        +String provider
        +String apiType
        +String category
        +String description
        +String baseUrl
        +String apiKey
        +Integer timeout
        +String status
        +String createNo
        +String updateNo
        +Date createTime
        +Date updateTime
        +Boolean deleted
        +save(operatorId)
        +delete(operatorId)
        +enable(operatorId)
        +disable(operatorId)
    }

    class ModelRepository {
        +findById(id)
        +findByNum(num)
        +findByCode(code)
        +list(page, keyword, provider, status, category)
        +listEnabled()
        +save(model, operatorId)
        +delete(num, operatorId)
    }

    Model --> ModelRepository : 依赖
```

| 对象 | 类型 | 属性 | 与其它对象关系 |
|------|------|------|--------------|
| Model | 聚合根 | id、num、modelCode、modelName、provider、apiType、category、description、baseUrl、apiKey、timeout、status、createNo、updateNo、createTime、updateTime、deleted | 聚合根 |
| ModelRepository | 仓储接口 | findById、findByNum、findByCode、list、listEnabled、save、delete | 操作 Model 聚合 |

#### 3.2.2 领域规则

| 聚合/对象 | 规则类型 | 规则描述 | 违反时表达 |
|-----------|---------|---------|-----------|
| Model | 不变性 | modelCode 全局唯一 | 抛出 MODEL_CODE_ALREADY_EXISTS |
| Model | 业务规则 | status 枚举值限定：ENABLED / DISABLED / ERROR | 状态转换时校验 |
| Model | 业务规则 | category 枚举值限定：文本模型 / 视觉模型 / 语音模型 / 全模态模型 | 校验时拦截 |
| Model | 业务规则 | timeout 取值范围：1-300 秒 | 抛出 MODEL_TIMEOUT_INVALID |
| Model | 业务规则 | baseUrl 必须为合法 URL 格式 | 抛出 MODEL_CONNECTIVITY_TEST_FAILED |

#### 3.2.3 领域动作

| 聚合/实体 | 领域动作 | 职责 | 前置条件 | 后置条件/规则 | 领域事件 |
|-----------|---------|------|---------|--------------|---------|
| Model | save(operatorId) | 新建或更新模型 | modelCode 不重复、baseUrl 合法 | 自动设置 status=ENABLED（新建时），更新 updateTime | ModelCreatedEvent / ModelUpdatedEvent |
| Model | delete(operatorId) | 逻辑删除模型 | 禁用状态才可删除 | 标记 deleted=1，更新 updateTime | ModelDeletedEvent |
| Model | enable(operatorId) | 启用模型 | status != ENABLED | status=ENABLED，更新 updateTime | ModelStatusChangedEvent |
| Model | disable(operatorId) | 禁用模型 | status != DISABLED | status=DISABLED，更新 updateTime | ModelStatusChangedEvent |

**save 时序图**：

```mermaid
sequenceDiagram
    participant Svc as ModelCommandService
    participant M as Model
    participant Repo as ModelRepository
    participant EP as EventPublisher

    Svc->>Repo: findByCode(modelCode)
    alt 编码已存在
        Repo-->>Svc: throw MODEL_CODE_ALREADY_EXISTS
    end
    Svc->>M: new Model()
    Svc->>M: save(operatorId)
    Note over M: 新建时 status=ENABLED
    Svc->>Repo: save(model, operatorId)
    alt 新建
        Svc->>EP: publish(ModelCreatedEvent)
    else 更新
        Svc->>EP: publish(ModelUpdatedEvent)
    end
    Svc-->>Ctrl: return ModelVO
```

| ModelDeletedEvent | 删除模型后 | modelNum, modelCode, operatorId, eventTime | 审计日志 |

| ModelTestedEvent | ~~连通性测试完成后~~ | ~~modelNum, success, connectivityStatus, eventTime~~ | ~~审计日志、告警~~（已废弃） |

### 6.2 DDL 语句

> **说明**：现有 `model` 表包含大量扩展字段（temperature、top_p、maxTokens 等），按 PRD 精简后不纳入核心流程。以下为当前表结构，`connectivity_status`、`last_test_time`、`test_error_message` 字段不再使用。

```sql
-- Model 表（已存在，init.sql 第 244 行）
CREATE TABLE `model` (
    `id`                    BIGINT         NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    `model_code`            VARCHAR(64)    NOT NULL                COMMENT '模型编码',

    `api_type`              VARCHAR(32)    DEFAULT 'openai'        COMMENT 'API类型',
    `description`           VARCHAR(1000)  DEFAULT NULL            COMMENT '描述',
    `category`              VARCHAR(64)    DEFAULT NULL            COMMENT '分类',
    `sort_order`            INT            DEFAULT 0               COMMENT '排序',
    `api_key`               VARCHAR(512)   DEFAULT NULL            COMMENT 'API密钥(加密存储)',
    `base_url`              VARCHAR(512)   DEFAULT NULL            COMMENT 'API地址',
    `timeout`               INT            DEFAULT 30              COMMENT '超时时间(秒)',
```

## 11. 其他

### 11.1 AES 加密

复用现有 `infra/common/AesEncryptor`，密钥优先读取环境变量 `AES_ENCRYPT_KEY`。

- 创建/更新模型时：`AesEncryptor.encrypt(apiKey)` 加密后存储
- 查询详情时：API Key 不返回明文，列表完全隐藏，详情脱敏展示（`sk-****abcd`）
- 前端脱敏逻辑：后端返回 `apiKeyMasked` 字段（如 `sk-****abcd`），前端直接展示

### 11.2 Agent 资源绑定查询

模型删除前校验：禁用状态才可删除（通过前端隐藏非禁用状态的删除按钮实现）。Agent 资源绑定关系通过 `agent_resource_binding` 表（resourceType=MODEL）维护。

```sql
SELECT COUNT(*) FROM agent_resource_binding
WHERE resource_type = 'MODEL' AND resource_id = ?;
```

### 11.3 权限控制

- 所有模型操作（创建/编辑/删除/启用/禁用）仅限管理端（系统管理员/Agent 管理员）
- 通过现有 RBAC 权限系统控制，在 `SecurityConfig` 中配置 Model 相关权限规则
- 已启用模型查询（`/api/model/query/enabled`）可供 Agent 域内部调用，不受管理端权限限制
- 普通用户端不展示任何模型管理功能和页面

- 现有 `ModelRepository.listEnabled()` 方法已存在，直接复用
